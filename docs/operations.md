# Operations

Runbook for the parts of operating this service that are not covered by the deployment
checklist: migrations, backups, and monitoring.

## Database migrations

The schema is managed with Alembic. Migrations live in `migrations/` and are applied
automatically when the API container starts (the entrypoint runs `alembic upgrade head`
before uvicorn).

Apply manually when developing against a local Postgres:

```bash
alembic upgrade head          # forward
alembic downgrade -1          # one step back
alembic revision --autogenerate -m "describe change"
```

When introducing a change to `src/db/schema.py`, generate a revision and review the
autogenerated diff before committing — autogenerate does not detect every change (renames,
data backfills, or the `tsvector` trigger need hand-written `op.execute` calls).

**Pre-existing databases** that were created with the old `create_all` bootstrap should be
stamped to the current head so Alembic does not try to re-create existing tables:

```bash
alembic stamp head
```

## Backups

`scripts/backup.py` snapshots Postgres and Qdrant to a timestamped directory. Run it on a
schedule (cron or your orchestrator) and keep the output off-server.

```bash
python scripts/backup.py --target ./backups --keep 7
```

What it captures:

- **Postgres** — a `pg_dump` of the whole database (tenants, users, parent documents, FTS
  chunks).
- **Qdrant** — a collection snapshot via the snapshot API, which captures vectors and
  payloads consistently.
- **Local files** — the manifest and BM25 index from the `rag_data` volume, if present.

### Restore

```bash
# Postgres
docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" < backups/.../postgres.dump

# Qdrant
docker compose exec qdrant curl -X PUT "http://localhost:6333/collections/{name}/snapshots/restore" \
  -H 'Content-Type: application/json' \
  -d '{"location": "file:///qdrant/snapshots/....snapshot"}'
```

The named volumes to preserve are `pg_data`, `qdrant_data`, and `rag_data` — see
`docker-compose.yml`.

## Monitoring

Prometheus metrics are exposed at `/metrics` (auth-gated with a tenant API key). A scrape
config only needs the key as a header:

```yaml
scrape_configs:
  - job_name: rag-api
    scheme: http
    authorization:
      credentials: <tenant-api-key>
    static_configs:
      - targets: ["api:8000"]
```

Useful series:

| Metric | Meaning |
|---|---|
| `http_requests_total` | Request count by handler/status |
| `http_request_duration_seconds_*` | Latency percentiles |
| `rag_pipeline_decisions_total` | Pipeline outcomes (`answered`, `declined`, …) |
| `rag_cache_hits` / `rag_cache_misses` | Semantic-cache effectiveness |

The health endpoints are the first thing to alert on:

- `GET /health/live` — process is up.
- `GET /health/ready` — every required dependency probed; returns `503` when degraded.

## LangSmith tracing and evaluation

Set `LANGSMITH_API_KEY` and `LANGSMITH_TRACING=true` in `.env` to trace every query end to
end in LangSmith (one `RAGPipeline.run` span per query, tagged with the tenant id). There is
no other wiring — `src/observability/tracing.py` applies the settings at startup.

Evaluate against the golden query set:

```bash
python scripts/eval_langsmith.py                        # upload the golden set + score
python scripts/eval_langsmith.py --dataset my-project   # custom dataset name
```

This uploads runs and feedback (`source_citation_accuracy`, `faithfulness_passed`) to
LangSmith for the same `golden_queries.json` used by the offline `run_eval.py` harness.

## Common runbooks

**Rotate an admin key** — set a new `ADMIN_API_KEY` in `.env` and restart the api service.

**Deactivate a tenant** — `PATCH /admin/tenants/{id}/deactivate` (admin key) or
`python scripts/manage_tenants.py deactivate --id <id>`.

**Inspect retrieval for a query** — `python scripts/debug_retrieval.py --query "..." --tenant <id>`
against a running stack.

**Restart after ingestion** — the api process builds retrieval components once; restart it
so a freshly created keyword index is loaded:

```bash
docker compose restart api
```
